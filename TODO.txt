2. IMPLEMENTER Simulator.run(graph)  -- PSEUDO-CODE
----------------------------------------------------------------

2.1 Etat a ajouter a la classe Drone (utils/graph.py) :

    Drone:
        id            # identifiant unique
        path          # liste des zones a parcourir
        index         # position actuelle dans path (commence a 0)
        in_flight     # True si en vol vers une zone restricted
                      # (sur la connexion)
        delivered     # True si arrive a end

2.2 Boucle principale :

    FONCTION run(graph):
        TANT QUE tous les drones ne sont pas delivered:
            moves = []          # mouvements de ce tour (affichage)
            occupancy = {}      # nb de drones par zone APRES ce tour
            link_usage = {}     # nb de drones par connexion ce tour

            # IMPORTANT : trier les drones par index DECROISSANT
            # (le plus avance d'abord -> il libere sa zone pour
            #  celui qui le suit, dans le MEME tour)

            POUR CHAQUE drone non delivered:

                # CAS 1 : drone en vol vers une zone restricted
                SI drone.in_flight:
                    # il DOIT atterrir ce tour (regle du sujet)
                    drone.index += 1
                    drone.in_flight = False
                    dest = drone.path[drone.index]
                    moves.ajouter("D{id}-{dest}")
                    occupancy[dest] += 1
                    SI dest == end: drone.delivered = True
                    CONTINUER

                # CAS 2 : drone au sol, tente d'avancer
                dest = drone.path[drone.index + 1]

                # verifier la capacite de la connexion pos->dest
                SI link_usage[(pos, dest)] >= max_link(pos, dest):
                    occupancy[pos] += 1     # connexion saturee, attend
                    CONTINUER

                SI dest est restricted:
                    # cout 2 tours : le drone part sur la CONNEXION
                    # MAIS il faut garantir qu'il pourra atterrir au
                    # tour suivant (interdit d'attendre sur la connexion)
                    SI atterrissage possible au tour suivant:  # cf 2.3
                        drone.in_flight = True
                        link_usage[(pos, dest)] += 1
                        moves.ajouter("D{id}-{pos}-{dest}")  # nom connexion
                    SINON:
                        occupancy[pos] += 1                  # il attend
                SINON:
                    # zone normale / priority / end : cout 1 tour
                    SI dest == end OU occupancy[dest] < max_drones(dest):
                        drone.index += 1
                        link_usage[(pos, dest)] += 1
                        occupancy[dest] += 1
                        moves.ajouter("D{id}-{dest}")
                        SI dest == end: drone.delivered = True
                    SINON:
                        occupancy[pos] += 1     # zone pleine, attend

            afficher(moves joints par des espaces)   # 1 ligne = 1 tour
            turns += 1

2.3 Points delicats :

    a) Liberation de capacite le meme tour
       Le sujet dit : "Drones moving out of a zone free up capacity
       for that same turn". Le tri par index decroissant gere ca :
       le drone en tete quitte sa zone d'abord -> la place liberee
       est visible pour le drone derriere lui dans le meme tour.
       C'est pour ca qu'on construit occupancy au fil du tour
       (etat APRES mouvements), pas depuis l'etat du tour precedent.

    b) Zones restricted : avant d'engager un drone sur la connexion,
       verifier qu'il pourra FORCEMENT atterrir au tour suivant :
         capacite de la zone restricted >=
           (drones deja dedans qui ne partiront pas)
           + (drones deja en vol vers elle) + 1
       Approximation prudente :
         nb_en_vol_vers(dest) + occupancy_estimee(dest)
           < max_drones(dest)
       Si pas garanti -> le drone attend au sol (toujours valide).

    c) Nom de la connexion pour l'affichage D<ID>-<connection> :
       la connexion s'appelle <zone1>-<zone2> comme dans le fichier
       de map (ex : D3-hub2-restrictedZone).

    d) End zone : pas de limite de capacite a l'arrivee (les drones
       livres ne sont plus suivis) -> ne pas compter end dans
       occupancy.

    e) Garde-fou anti-boucle infinie : si pendant un tour AUCUN
       drone n'a bouge -> lever une erreur (deadlock, utile pour
       debugger les maps hard).

3. FORMAT DE SORTIE (section VII.5 du sujet)
----------------------------------------------------------------

    - Une ligne par tour, mouvements separes par des espaces :
        D<ID>-<zone>
    - Drone en vol vers une zone restricted :
        D<ID>-<connection>
    - Les drones qui ne bougent pas sont OMIS de la ligne.
    - Un drone arrive a end n'est plus suivi.
    - Fin quand TOUS les drones sont livres.

    Exemple :
        D1-roof1 D2-corridorA
        D1-roof2 D2-tunnelB
        D1-goal D2-goal
